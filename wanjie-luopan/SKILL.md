# 万界罗盘

把模糊想法转成有证据、值得打开的开源项目路引。默认只完成低成本的发现与初筛；只有用户明确要求时，才进入仓库深查或运行验证。

当前 Skill 实现主动发现、候选对比、仓库深查和按需运行验证。产品语言中的“巡天”（持续发现）、“星历”（更新追踪）和“藏卷”（个人项目库）属于后续产品能力；未真正实现前不得声称可用。

## 核心约束

- 使用当前可验证的真实来源；不要编造仓库、指标、许可证或运行结果。
- 分开标注作者声称、仓库证据、社区证据和本地运行证据。
- 优先回答“为什么值得继续看”，不要默认讨论变现。
- 把 Star 当热度信号，不当成熟度、用户量或质量证明。
- 先过硬门槛，再评分；不要用总分掩盖许可证、空壳或不相关问题。
- 默认不克隆、不安装、不执行仓库代码，控制时间、Token 和环境风险。
- 未找到或未验证时直接说明，不用推测补齐。

## 选择工作模式

1. **路引（快速发现）**：用户给出方向，希望找到项目。建立候选池并返回 3–8 个值得看的项目。默认使用此模式。
2. **星图（候选对比）**：用户给出多个仓库或要求比较。统一证据口径，给出不同用途下的优先级和项目关系。
3. **开卷（仓库深查）**：用户要求“完整看下”“是否值得用”。检查真实文件、维护、Issues、Release、许可证和入口。
4. **最小运行验证**：用户明确要求安装、运行或测试。只验证最终 1–2 个项目，使用隔离目录和最小核心工作流。

若用户只说“找项目”，不要自动升级到模式 3 或 4。

## 工作流

### 1. 建立搜索简报

提取：目标问题、希望看到的项目形态、平台/技术栈、必须项、排除项和时间范围。信息不足时先做合理假设；只有会显著改变结果时才问一个简短问题。

### 2. 发现候选

读取 [discovery-strategy.md](references/discovery-strategy.md)。扩展问题词、实现词、相邻类别和已知项目关系。优先使用 GitHub 官方页面/API、项目官网和原始文档；需要当前指标时必须现场验证。

路引模式建立约 10–20 个候选池，并记录准确仓库 URL。合并镜像、Fork、改名仓库和同一项目的不同入口。

### 3. 硬门槛筛选

读取 [screening-rubric.md](references/screening-rubric.md)。先排除或降级：不存在、无实质代码、明显不相关、许可证不明或不兼容、核心依赖失效、长期停更且无人接手、README 与代码严重不符的项目。

需要一致排序时，把候选整理为 JSON，并运行：

```bash
python3 scripts/score_candidates.py candidates.json --pretty
```

评分只能排序已通过硬门槛的候选，不能替代人工证据判断。

### 4. 输出分层短名单

读取 [evidence-levels.md](references/evidence-levels.md) 和 [report-format.md](references/report-format.md)。默认分成：

- 立即值得看：最相关且已有实质证据
- 备选：方向相关，但成熟度、证据或维护性稍弱
- 只看思路：有启发，但不宜当可靠底座
- 已排除：列出少量容易误选的项目与原因

不要强行给唯一“最优选择”。说明每个项目最值得先看的入口、功能或文件。

### 5. 按需深查

只对用户选中或明确要求的仓库进行深查：

- 确认项目真实形态：应用、库、Skill、工作流、服务、模型或原型
- 对照 README 与文件树、入口、依赖、脚本、测试和构建路径
- 检查最近提交、Release、贡献者、Issues/PR 和维护节奏
- 检查许可证、NOTICE、素材、模型、数据和商标边界
- 给出“已验证 / 未验证 / 推断”，不要把能安装等同于适合长期使用

涉及许可证判断时读取 [license-boundary.md](references/license-boundary.md)。

### 6. 按需运行验证

只验证最终 1–2 个项目：

- 使用临时或用户指定目录，先检查运行时和版本要求
- 优先 dry-run、帮助命令、测试和最小示例
- 不把密钥写入仓库，不触碰生产数据，不默认发送、发布或部署
- 记录准确命令、成功项、失败项、环境阻塞和恢复方法
- 没有运行证据时，不说“已经跑通”

## 交付标准

最终答案必须包含：

1. 搜索目标与本次假设
2. “立即值得看”短名单
3. 每个候选的准确链接、项目形态、推荐理由、证据等级和主要风险
4. 备选与关键排除项
5. 已验证、未验证和本次没有做的事情
6. 最自然的下一步，例如深查某一仓库，而不是自动扩张任务

只有用户明确要求保存研究材料时，才把报告写入工作区。

## 停止与降级

- 当前来源无法访问时，说明受阻范围；不要用旧记忆冒充当前事实。
- 搜索结果不足时，返回少量高置信候选，并列出已尝试的查询方向。
- 候选之间证据层级不一致时，不做精确排名，先补齐同一层级的证据。
- 运行需要登录、付费、密钥或外部副作用时，在对应动作前取得用户授权。
