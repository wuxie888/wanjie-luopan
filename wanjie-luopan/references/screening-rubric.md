# 筛选规则

## 硬门槛

出现以下情况时直接排除或降为“只看思路”：

- 仓库不存在、已删除或链接无法确认
- 没有实质代码，只有 README、截图或占位文件
- 与目标只存在关键词相似，核心问题不同
- 无许可证且用户需要复用或二次开发
- 许可证明确与目标用途不兼容
- 核心模型、数据、服务或依赖已经不可用
- README 与当前代码结构明显不符
- 项目已长期停更，且不存在社区接手、稳定 Release 或仍可用证据

仅做“找项目来看”时，无许可证不必完全排除，但必须醒目标记“仅供研究，不应默认复用”。

## 软评分

每项使用 0–5 分：

| 字段 | 权重 | 说明 |
| --- | ---: | --- |
| relevance | 30 | 与目标问题和项目形态的真实相关度 |
| novelty | 15 | 是否提供独特实现、视角或学习价值 |
| substance | 15 | 代码、入口、示例和工程结构是否实质完整 |
| activity | 10 | 维护节奏、贡献者和问题处理情况 |
| documentation | 10 | 能否理解、安装和定位核心能力 |
| usage_evidence | 10 | Demo、Release、社区使用或真实案例证据 |
| legal_safety | 10 | 许可证、素材、数据和依赖边界的清晰程度 |

总分仅用于同层级候选排序：

- 80–100：立即值得看
- 65–79：备选
- 50–64：只看思路
- 低于 50：通常排除

## 不要误用的指标

- Star：热度，不是质量或用户量
- Fork：可能是活动，也可能只是传播
- 最近提交：不代表核心功能稳定
- Release 数量：需要同时看时间、内容和可安装性
- Issue 数量：高低都不能独立判断健康，需要看响应和关闭情况
- README 截图：只证明作者展示过画面，不证明当前版本可运行
