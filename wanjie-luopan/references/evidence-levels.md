# 证据等级

## E0 线索

仅看到搜索摘要、社交帖子、榜单、仓库标题或他人转述。

允许表述：“发现了这个候选”“作者/帖子声称”。
禁止表述：“项目支持”“已经可用”。

## E1 仓库表面证据

已打开真实仓库，核对 README、文件树、许可证、提交或 Release 页面。

允许表述：“仓库包含”“README 说明”“当前页面显示”。
仍不能表述：“已经跑通”。

## E2 工程证据

已检查入口、依赖、脚本、测试、关键源码、Issues 或构建配置，README 声称与代码能相互印证。

允许表述：“代码实现了”“存在可执行入口”“发现兼容性风险”。
若未运行，必须写明“代码证据，未做本地运行”。

## E3 运行证据

已在明确环境执行安装、测试或核心工作流，并记录命令和结果。

允许表述：“在本次环境已运行”“该核心流程已验证”。
运行一个示例不等于生产可用；仍需区分稳定性、安全和长期维护。

## 冲突处理

证据冲突时按以下顺序处理：

1. 本次可复现运行结果
2. 当前源码和测试
3. 当前 Issues、Release 和官方文档
4. README
5. 社交帖子和第三方转述

保留冲突本身，不替作者解释。
