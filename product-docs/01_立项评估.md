# 立项评估

## 结论

通过轻量立项。先做全局 Skill，不直接做公共产品。

## 用户问题

用户每次寻找开源项目都要重复构造关键词、筛噪声、打开仓库、核对真实性和解释证据边界。

## 现有替代方案

- GitHub 搜索：覆盖广但缺少语义和证据判断
- 通用 AI 搜索：表达好但容易停在摘要或 README
- Awesome List：适合导航，不适合具体目标排序
- 手工浏览：可靠但重复且耗时

## 成功标准

- 真实任务的前三名中至少两个值得继续看
- 不编造仓库、指标或许可证
- 关键判断标明证据层级
- 默认不触发克隆和运行

## 最大风险

把主观评分包装成客观结论，或为了候选数量引入低质量结果。
